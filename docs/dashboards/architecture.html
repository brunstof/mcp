Architecture

How a request flows through the server

An AI client speaks MCP over one of three transports. FastMCP routes the call to a registered tool, which passes through the read-only query gateway before reaching the async connection pool and MariaDB. Vector tools additionally call the embedding service.

3 · Vector search — request sequence

How search_vector_store turns a natural-language query into a ranked result set.

sequenceDiagram
  autonumber
  participant AI as AI Client
  participant MCP as FastMCP / MariaDBServer
  participant EMB as EmbeddingService
  participant POOL as asyncmy Pool
  participant DB as MariaDB

  AI->>MCP: search_vector_store(db, store, user_query)
  MCP->>EMB: embed(user_query)
  EMB-->>MCP: query vector (e.g. 1536 / 768 / 1024-dim)
  MCP->>POOL: acquire connection
  POOL-->>MCP: connection
  MCP->>DB: SELECT ... ORDER BY VEC_DISTANCE(embedding, ?) LIMIT k
  DB-->>MCP: nearest documents + metadata
  MCP-->>AI: ranked results (JSON)
